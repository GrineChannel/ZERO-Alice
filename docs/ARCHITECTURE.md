# ZERO: Alice — архитектура и план перестройки

Статус: рабочий план. Исходная версия сохранена в ветке `backup-before-architecture-rebuild-2026-11-11`.

## Цель
Построить устойчивое Android-приложение с локальным ИИ, памятью, голосом и управляемыми инструментами. Инженерная лаборатория Minecraft — отдельный модуль, а не основа приложения.

## Принципы
1. Сохранять существующие функции и локальные пользовательские данные при обновлениях APK.
2. Одна ответственность на компонент; `MainActivity` отвечает за жизненный цикл и навигацию, не за бизнес-логику.
3. Долгие операции выполняются вне UI-потока; UI получает состояние и ошибки.
4. Одна инициализация LiteRTLM, контролируемое завершение, отсутствие одновременной генерации без очереди.
5. Явные состояния задач, повторные попытки и безопасное восстановление после сбоя.
6. Локальная память по умолчанию; просмотр, отключение и удаление данных должны быть доступны пользователю.
7. Файловые операции ограничены каталогом проекта, с резервным копированием и проверкой путей.
8. Сборка APK, проверка формата аддона и запуск в Minecraft — три разные проверки. Не называть статическую проверку игровым тестом.
9. Каждое изменение: один небольшой коммит, проверка GitHub Actions, затем проверка на устройстве.

## Предлагаемые слои
- `ui/` — экраны и визуальные состояния.
- `navigation/` — переходы и обработка «Назад».
- `ai/` — управление локальной моделью и очередью запросов.
- `chat/` — диалоги и контекст.
- `memory/` — хранение, извлечение, удаление и настройки памяти.
- `storage/` — общие безопасные операции с файлами и экспорт.
- `engineer/` — планирование, генерация, проверка и сборка дополнений.
- `voice/` — будущий голосовой интерфейс.

Это целевая структура; текущие пакеты не перемещаются одним большим изменением.

## Этапы
1. **Базовая устойчивость**: навигация, обработка ошибок, состояние фоновых операций, сохранность данных, тесты.
2. **Локальный ИИ**: единый жизненный цикл модели, изолированные запросы, тайм-ауты и отмена.
3. **Чат и память**: корректное забывание, настройки, проверяемое поведение.
4. **Голос и инструменты**: разрешения, прозрачное подтверждение опасных действий.
5. **Инженерная лаборатория**: валидатор, журнал задач, экспорт, тесты Minecraft.
6. **Автоматизация**: безопасная очередь работ и восстановление после перезапуска.

## Выявленные риски на старте
- `MainActivity` смешивает навигацию, загрузку модели, чат и запуск инженера.
- В `AliceMinecraftValidator` зависимости по `module_name` могут ошибочно считаться невалидными UUID.
- Команда «забудь» удаляет факты, но может оставлять сведения в истории сообщений.
- Сгенерированный JavaScript не исполняется при текущей статической проверке.
- Экспорт `.mcaddon` в доступную пользователю папку ещё не подключён к интерфейсу.
- Для инженерных задач нет надёжного возобновления после остановки приложения.

## Первый технический шаг
Выделить состояние навигации из `MainActivity` с сохранением существующих экранов и поведения кнопки «Назад». Перед рефакторингом проверить сборку текущего `main`.
